How an outage works

  1. You pick a service and a fault, and it goes into a simulated shop of 11 services. The charts above are its telemetry, played faster than real time.
  2. The alarm fires when a metric stays 4σ above normal for 15 s. No AI is involved yet.
  3. Claude investigates with read-only tools: metrics, logs and the call graph. Every tool call streams into the flight log.
  4. A plain-code verifier checks every suspect's evidence. The agent answers only when its top suspect is verified and confident; otherwise it escalates to a human.
  5. The scoreboard compares your guess, the agent and a no-AI z-score ranking.

Or replay any recorded investigation for free, and see the numbers under Evidence.

How well does the agent work?

132 outages, three for every service × fault type, on seeds that were never looked at while the agent was built. "Named the cause first" means the true cause was ranked first and accepted by the verifier. Every run, with each tool call and the model's reasoning, can be replayed under Replay.

The telemetry is simulated: caller logs name the failing service and faults are single and clean, so the absolute numbers are optimistic. The no-AI baseline runs on exactly the same data, so the comparison is fair.
